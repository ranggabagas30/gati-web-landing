# GATI Landing Page — v2.0 Revamp Design

Status: Approved for planning
Date: 2026-08-15
Source mockup: `docs/backlogs/revamp-v2.0/draft-v2.0.html`

## 1. Goal

Replace the current landing page implementation with a full rebuild matching
`draft-v2.0.html`: a dark-themed, single-page site with an intro sequence, a
scroll-driven cycling hero, a numbered expertise grid, a sticky-index project
showcase, and an in-page case-study overlay — ported into this codebase's
React/TypeScript/Vite/Tailwind/GSAP stack, not copied as static markup.

This is a full replacement, not an incremental skin. The current light-themed
sections, their copy, and their visual conventions are not preserved except
where explicitly noted below.

## 2. Scope Decisions

These were resolved during brainstorming and are binding for the plan:

| Decision | Resolution |
|---|---|
| Case-study delivery | Full slide-up overlay (`#cs-overlay` equivalent), replacing the current hash-route `PortfolioDetailPage`. Built with React performance best practices: lazy-loaded per-project content, deferred images. |
| "World Switcher" (CODE / ART) | Stub only. Rendered as designed, but is a decorative/no-op element this phase. No second site variant is built. |
| Intro sequence (wall/tap-to-enter/flying logo/cycling hero) | Full fidelity, ported to React state/effects. Session-gated (plays once per browser session). |
| S2 hero auto-advance + scroll-to-skip | **Removed.** Replaced with scroll-driven manual advance (see §4.2). |
| Orphaned sections (`ManifestoSection`, `ServicesSection`, `TeamSection`, `ServicesListSection`, `Footer` v1) | Retired entirely — deleted, not just unmounted. |
| Pricing section (`s5`) | **Dropped entirely.** Expertise section's per-card "typically starts at $X" already communicates pricing; no separate pricing section is built. |
| S4 sticky rail | Confirmed broken in the source mockup (verified via screenshot — rail scrolls away with the page instead of pinning). Root cause not fully diagnosed in the disposable mockup; the React rebuild avoids the whole bug class via CSS Grid instead of flex (see §5). |

## 3. Architecture

### 3.1 Routing simplification

`App.tsx` currently branches between `LandingPage` and `PortfolioDetailPage`
via a hand-rolled hash router. Since case studies become an in-page overlay
rather than a route, this branching is removed. `App.tsx` renders
`LandingPage` unconditionally.

A thin hash listener is kept *only* for case-study deep-linking:
`#/portfolio/<slug>` on load opens the matching case-study overlay over the
landing page; closing the overlay clears the hash back to `#/`. This reuses
the existing hash-parsing utility rather than reviving full-page routing.

## 4. Section-by-Section Behavior

### 4.1 Nav + Intro Sequence

`Nav.tsx` owns the full first-load sequence, implemented as a state machine
(`'wall' | 'entering' | 'settled'`) driving CSS transitions via
`useIntroSequence()`:

1. Cream "wall" overlay covers the viewport with a pulsing "Tap to enter"
   hint.
2. On tap (or first scroll/wheel/touch input), the logo animates from center
   into the nav slot while the wall fades out.
3. Nav links rise in, the divider draws, and the hero (S2) begins its
   scroll-driven sequence (§4.2).

Gated via `sessionStorage` (`gati_intro_done`) so it plays once per session;
within the same session, returning to the page renders nav/hero already
settled (skip path), matching the draft's `showPage()` behavior.

Mobile nav gets a hamburger menu — not present in the draft at all (no
mobile nav media query exists in the source CSS). The intro sequence applies
identically on mobile; only the settled nav layout differs (links collapse
into a drawer below 860px).

### 4.2 S2 Hero — scroll-driven, not timer-driven

Three statements (word-by-word rise/exit, inverted layout for the final
payoff line) cycle based on user scroll input, not a timer:

- The section is pinned (page scroll captured) while any statement other
  than the last is showing.
- Each wheel tick or touch swipe forward advances one statement
  (st1 → st2 → st3). Scrolling backward while pinned steps back a statement.
- Scrolling forward *past* the final statement unpins the section and
  resumes normal page scroll into S3.
- Trackpad/wheel input is delta-accumulated with a ~150–200ms cooldown per
  advance, since one physical scroll gesture fires many wheel events — a
  raw per-event listener would blow through all three statements on one
  swipe.
- Transition durations are compressed relative to the draft (~250–300ms for
  word rise/exit and sub-line fades, vs. the draft's ~550–600ms) so each
  statement registers quickly without a long forced hold, avoiding a "stuck"
  feeling now that there's no timer pacing the read.

Implemented as `useScrollDrivenHero()` — plain React state/effects, not
GSAP (this is discrete stepped state, not a scrubbed/tweened value).

### 4.3 S3 Expertise

Three dark, numbered cards (01/02/03):

| # | Title | Price | Hover image |
|---|---|---|---|
| 01 | Super-App Platforms | $10,000 | `1 - 3 expertise card images.png` (CuanX) |
| 02 | Complex Interactive Platforms | $5,000 | `2 - 3 expertise card images.png` |
| 03 | Brand Websites | $2,000 | `3 - 3 expertise card images.png` |

- Grid-textured card background, border turns orange on hover, orange
  bottom line scales in on hover.
- Hover-reveal image panel (`translateY(100%→0)`) rises from the bottom via
  CSS `:hover`/`:focus-within` — no JS state needed for the reveal itself.
  Gated behind `@media (hover: hover)`; touch devices show the reveal image
  at low static opacity by default instead of simulating hover.
- Price tag scrambles into place on `mouseenter` (digit-scramble via
  `requestAnimationFrame`, ported from the draft's `scramble()`), reverts to
  the formatted value on `mouseleave`/blur. Implemented as
  `usePriceScramble()`.
- Entrance animation: existing GSAP `fromTo` opacity/y stagger pattern,
  unchanged from the current codebase convention.

### 4.4 S4 Projects

- Sticky left rail (section label, 01/02/03 index list, live meta panel,
  CTA) built with **CSS Grid** (`grid-template-columns: 300px 1fr`), not
  flex — see §5 for why.
- `useProjectScrollSpy()` (`IntersectionObserver`) tracks which project row
  is in view and updates the active index/meta panel content. This is
  separate from the sticky positioning itself, which is pure CSS and
  requires no JS.
- Each project row ends in a "View Case Study" trigger that opens
  `CaseStudyOverlay` for that slug instead of navigating away.

### 4.5 Case Study Overlay

- Slide-up panel (`translateY(100%→0)`), sticky topbar with back/close
  controls.
- Content per project is code-split: `React.lazy()` + `Suspense` per
  `caseStudy/*.tsx` module, so no case-study copy/markup ships in the main
  bundle until a case study is actually opened.
- Data ported from the draft's `CS_DATA` into `caseStudyData.ts` — content
  is copy-complete in the source; empty image placeholders are filled from
  existing `public/images/portfolio/*` assets (already used by the retired
  `PortfolioDetailPage`, so these are reused, not re-sourced).
- Opening sets a body scroll-lock and updates `location.hash` for
  deep-linking (`#/portfolio/<slug>`); closing restores prior scroll
  position and clears the hash back to `#/`.

### 4.6 S6 Footer

Two-column headline + CTA card, contact row (email + social links), giant
SVG wordmark. Direct port of the draft's `s6` — least novel section,
existing GSAP entrance pattern applies to each block.

## 5. S4 Sticky Rail — Bug Avoidance

The source mockup's sticky rail was confirmed broken by screenshot: the top
of the rail (section label + index buttons) had already scrolled off past
the nav while the bottom of the rail (meta tail + story + CTA) was still
mid-scroll — i.e., the whole block was scrolling with the page as a normal
in-flow element rather than pinning as one unit under the nav.

The mockup's own CSS shows an awareness of one common cause (a comment on
`.s4-inner { align-items: flex-start }` calling out a "Chrome sticky" fix),
but the bug persisted regardless. Rather than fully reverse-engineer a
disposable mockup, the rebuild avoids the entire bug class structurally:

- `.s4-left`-equivalent uses **CSS Grid** two-column layout
  (`grid-template-columns: 300px 1fr`, responsive per breakpoint) instead of
  flex. Grid items are not silently stretched to a sibling's height the way
  flex items are under default `align-items` behavior — the most common
  cause of "sticky element has no room to stick" bugs.
- No ancestor of the sticky rail (through to `body`) has `overflow`,
  `transform`, `filter`, or `contain` set outside of the intro
  sequence/overlay's temporary scroll-lock (both of which unlock correctly
  and are inactive during normal S4 scrolling).
- `top` is explicitly set to the nav height (64px equivalent) on the sticky
  element.

This is verified directly in the dev server once S4 is implemented (§7),
not assumed from the mockup.

## 6. Performance

- Case-study content (`caseStudy/*.tsx`) is `React.lazy()`-loaded — verified
  via build output / network tab that it code-splits into separate chunks
  not present in the initial bundle.
- Images reuse the existing `public/images/portfolio/*` assets (already
  processed by `scripts/optimize-images.js` / `sharp`) — no new image
  pipeline required. Below-the-fold images use `loading="lazy"`; overlay
  images are deferred until the overlay actually opens.
- Scroll listeners (S2's wheel/touch handling, S4's `IntersectionObserver`)
  are passive and torn down in `useEffect` cleanup, matching the existing
  `ScrollTrigger.kill()` cleanup convention already used throughout the
  codebase.

## 7. Responsive Strategy

Per CLAUDE.md's breakpoint targets (390 / 768 / 1280 / 1440 / 1920px). The
draft is desktop-first and has real gaps on mobile — most notably, no nav
media query exists at all in the source CSS. Gaps are filled as follows:

- **Nav**: hamburger drawer below 860px (new — not in the draft).
- **S2 Hero**: scroll-driven advance works via touch swipe; pin/unpin logic
  is identical, just touch-gated instead of wheel-gated.
- **S3 Expertise**: cards stack vertically below 860px (draft already
  specifies this). Hover-reveal degrades to always-partially-visible on
  touch devices per §4.3.
- **S4 Projects**: rail width shrinks 300px → 180px → 110px per breakpoint;
  meta panel hides below 480px, showing only the index list (draft's
  existing responsive rules, re-expressed as Grid column widths rather than
  flex-basis).
- **Case-study overlay**: single-column on mobile; feature grids and tech
  rows collapse to one column below 860px (draft already specifies this).

## 8. Testing / Verification Plan

- `npm run dev`; visually verify every section at 390 / 768 / 1280 / 1440 /
  1920px.
- Intro sequence plays once per session; skip path confirmed on repeat
  visits within the same session.
- S2 scroll-driven advance: forward/backward stepping, correct unpin
  timing, no double-advance from a single trackpad gesture.
- S4 sticky rail holds correctly under the Grid-based layout — confirmed in
  the dev server, not the mockup (see §5).
- Case-study overlay: open/close transitions, scroll-lock, deep-link via
  `#/portfolio/<slug>`, and confirmed code-splitting in build output.
- GSAP entrance animations clean up on unmount (no `ScrollTrigger` leaks) —
  matches the existing pattern already used in the codebase.

## 9. Non-Goals (explicit)

- No real "ART" world/second site — the World Switcher is a stub.
- No S2 auto-advance timer, no scroll-to-skip gesture.
- No S5 Pricing section.
- No preservation of `ManifestoSection`, `ServicesSection`, `TeamSection`,
  `ServicesListSection`, or `Footer` v1 content — all retired.
- No literal port of the mockup's vanilla JS/DOM-manipulation code — all
  interactions are re-implemented as React state/effects/hooks per the
  codebase's existing conventions.
